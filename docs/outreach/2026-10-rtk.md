Independent measurement: rtk with Claude Code: rewrites happen, bill unchanged (preliminary)
---
Hi! We're building skilllab (https://github.com/mekala540/skilllab), an open-source harness that measures agent add-ons by running the same coding tasks with and without them, checking the work with hidden tests, and comparing what Claude Code reports as cost.

**Setup:** Claude Code (headless) with claude-haiku-5-5, rtk 1.0.1 installed via Homebrew, the same PreToolUse hook entry that `rtk init -g --hook-only` installs, passed per run with `--settings` (we didn't run `rtk init`, so global settings stayed untouched), plus workspace allow rules so the hook returns "allow". 12 coding tasks in one project (git, grep, test runs, logs), 3 runs per task per arm, interleaved, with warm-up runs and a no-op control arm.

**What we saw:**
- The hook did fire: on the test machine, `rtk gain` lists rtk read ×24, rtk grep ×8, rtk git commit/diff/show, ls, find, and estimates ~380K tokens saved. (This is rtk's machine-wide counter, so it isn't in the linked data and may include a few earlier pilot runs.)
- Total cost per run vs. no rtk: **+2%** (90% range −1% to +5%). Pass rate 34/36 vs 32/36 (noise).
- Our reading: command output is a small share of each run's input next to the system prompt, tool definitions and cached context, so the saving doesn't show in the bill for these tasks. This matches what #2001 reported with the Claude Code SDK on different tasks.

**Data and method:** https://github.com/mekala540/skilllab/tree/main/docs/results/2026-10-17-project-tier

This is preliminary (one model, 12 tasks). Before we publish more widely, could you check whether we've set rtk up the way you'd recommend for Claude Code? Happy to rerun with any change you suggest.
